Built-in card labels: category, complexity, priority

The plan doc docs/plan/card-labels.md, which Obeya shows as a project in place of the idea. Nothing is built yet.

Goal

Every card gets built-in labels beside its priority: a category with a sub-category, and a complexity of 1, 2, 3, 5 or 8. Where the owner leaves a label empty, Obeya suggests one in the short session that already names a card, and marks it as its suggestion until the owner touches it. Which labels Obeya may suggest is a toggle per canvas; new canvases take their toggles from "Canvas defaults" in the Konfiguration dialog. The labels are the owner's only: stored in this Obeya, never in plan docs, not told to agents.

Shape

  • Fixed lists, the same for every repository. Category: Frontend, Backend, Data Migration, Docs, Tooling. Sub-category: Refactor, New feature, Bug fix, Configuration.
  • Complexity 1, 2, 3, 5, 8, with one line per step, the same text in the tooltip and in the suggestion skill.
  • Suggestions fill only empty labels and never overwrite. A purple border on the label chip marks them; any touch by the owner (same value, another one, or „Keine“) clears it.
  • Purple is not violet: the mark is on the chip only, never the card's frame, so it can't read as a proposal.
  • When: in the naming call for a card without a title; for a titled card, one short call at its start. No call when nothing is left to suggest.
  • „CLAUDE.md ergänzen“ gets Docs / Configuration from Obeya itself, marked as suggested.
  • Per-canvas toggles for Category, Complexity, Priority (on by default), and matching Canvas defaults; a test fails when a canvas setting has no default.

Workstreams

  • W1: Labels in the data and the API: fields, "suggested" marks, never-overwrite rule, lists in one shared place.
  • W2: Pickers and chips on the card, the purple suggested state, phone view.
  • W3: The suggestion skill and its hook into the naming session and the start.
  • W4: Canvas toggles „Obeya schlägt vor“, Canvas defaults, and the sync test.
  • W5: „CLAUDE.md ergänzen“ is labelled Docs / Configuration.
  • W6: Design docs updated; the plan doc goes.

Order: W1 first; W2, W3, W4 in any order after it; W5 needs only W1; W6 closes the project.
