Card labels: data and API

Each card now has a category, a sub-category and a complexity, beside its priority. They're stored in this Obeya, never in plan docs, and agents aren't told about them. The pickers and chips come in the next workstream; this run shows the rules the data follows. Every row below is real output from the new code, run step by step on one card.

The built-in lists (one shared place: src/core/labels.ts)

Category: Frontend, Backend, Data Migration, Docs, Tooling

Sub-category: Refactor, New feature, Bug fix, Configuration

Priority: trivial, low, medium, high, veryHigh, critical (unchanged)

Complexity: the same lines appear in the picker's tooltip and the suggestion prompt:

  • 1 A one-line or wording fix.
  • 2 A small change in one place.
  • 3 A change across a few files, with tests.
  • 5 A feature that touches both server and UI.
  • 8 A change that spans several areas or wants a plan doc.
