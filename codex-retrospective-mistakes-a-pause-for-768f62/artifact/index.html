A pause is no timeout: the Codex run excerpt

When a card finishes, Obeya draws an excerpt of what went wrong in the worker's run, and a small model turns it into friction notes for the work retrospective. For a Codex worker, a command the owner's pause had killed looked like a failed command, so the retrospective proposed a longer "Bash timeout", which Codex does not have.

The real Codex run from the live acceptance test (paused during bun run slow-check)

Before

26 tool calls, the first change to a file after 4.
1. Step 12 failed: Bash `bun run slow-check`
   Error: Exit code -1
   $ bun scripts/slow-check.ts
   slow-check: step 1 of 9 done
   …
   slow-check: step 4 of 9 done
The retrospective read this as a timeout and proposed adding a 300000 ms Bash timeout to CLAUDE.md.

After

No excerpt: nothing went wrong.

26 tool calls, step 12 cut off by
the owner's pause, 0 findings.
The rollout records the pause (the turn ends as "interrupted", then the command it was running ends with exit code -1). Obeya reads that as the owner's pause, stop or restart, not as the agent's failure, so the run makes no friction note.

A run with a pause and real friction (from the new test)

3 tool calls, no change to a file.
The owner paused, stopped or restarted the card during step 1: that call was cut off, no mistake of the agent's.
1. Steps 1–3: 3 similar Bash calls in a row, 1 failed:
   ⏸ `bun run slow-check` (cut off: the owner paused, stopped or restarted the card)
   ✗ `bun run slow-check`
   ✓ `bun run slow-check`
   Before: "I run the slow check."
   Error: Exit code 1
   slow-check: step 6 failed
When the run did go wrong besides, the excerpt still shows that, and it marks where the owner stepped in so the model does not blame the agent for it. An exit code -1 in a turn nobody interrupted still counts as the agent's failure.
