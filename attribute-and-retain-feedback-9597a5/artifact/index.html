Feedback is credited to the session that did the work

W1 of “Feedback on agent performance”: the storage behind the feedback prompt (W2) and the dashboard (W3). There is no new screen yet; this page shows what Obeya now records and how it decides whom a response credits.

What Obeya keeps

  • Every worker session is recorded with the harness, the model it actually resolved to (e.g. claude-opus-5-5, not the alias “opus”) and the effort it ran with, from the moment it starts. Changing the defaults later changes nothing about it.
  • Each response belongs to one handover of a card, with a stable link to the card, its title, repository and project as they were, the answer (a rating, a comment or both) and optional facets for later dimensions such as task type or complexity.
  • Whom a response credits is frozen when it is given: runs after that handover and later setting changes do not alter it.

Three outcomes

singleOne configuration did the workThat one is credited, even where a field is unknown.
mixedSeveral didAll are listed, none is credited alone, so no model gets credit for another's work.
missingNothing is knownNo model is credited; unknown is never filled in from today's defaults.

Clicking twice, or changing your mind

Sending the same response twice for “Export meter readings as CSV” left 1 stored response. Sending a different one for the same handover replaced the answer (rating 4 → 3, comment “Good, but missed the empty-file case.”) and kept whom it credits. A new handover gets a response of its own.

Refused before anything is kept:

  • {"answer":{}} → a response needs a rating or a comment
  • {"answer":{"rating":"great"}} → a rating is a number
  • {"answer":{"rating":4},"handover":999} → no such handover on the card
  • work not approved yet → only approved work takes feedback
  • card without a handover → the card has not handed over any work
