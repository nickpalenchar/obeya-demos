The server stays responsive while Obeya watches a Codex session's processes

While a Codex session runs, Obeya checks the machine's process list every half second to know which terminals belong to the agent. On a busy machine that list takes over a second to arrive. Before, the server waited for it and served no pages and heard no agents in the meantime; now it waits in the background.

Measurement: the tracker running for 6 seconds as during a Codex session, with ps slowed to 1.2 s as on a loaded machine. Red: stretches where the server could not answer anything.
