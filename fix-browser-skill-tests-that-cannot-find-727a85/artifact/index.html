Browser skill tests pass inside a Codex worker again

Two tests of the browser skill failed whenever they ran inside a Codex worker: each could not find its session's state file. Both runs below use the same environment as a Codex worker.

Before

4 pass · 2 fail
(fail) a session drives its own muted browser
       with trusted input, and it closes with the session
(fail) two sessions never share a browser;
       stop closes only its own

ENOENT: no such file or directory, open
'<temp>/obeya-browser/93499.json'

After

6 pass · 0 fail
(pass) a session drives its own muted browser
       with trusted input, and it closes with the session
(pass) two sessions never share a browser;
       stop closes only its own

Why the file was missing

The browser skill ties each browser to the agent session that started it. It recognizes that session by OBEYA_AGENT_PID, which Codex workers set, and otherwise by Claude Code's CLAUDE_PID. The tests simulate sessions by setting CLAUDE_PID, but they also passed on the worker's OBEYA_AGENT_PID, and that value wins. So every browser in the tests belonged to the worker, not to the simulated session: the state file was saved under the worker's ID, and the browser would not have closed when the simulated session ended.

The fix

The tests now remove OBEYA_AGENT_PID before starting the skill. The browser skill itself is unchanged: each session still gets its own browser, and the browser still closes with its session.
