Why extensions stopped getting “workerStarted”, and where it stands

Answer: worker startup did not become asynchronous. Event delivery broke: the line that sends workerStarted to extensions was lost in a refactor. It is already fixed on main.

What happened

CommitDateEffect
ceb8f8b7 “A worker that fails to start … goes to the owner, in red”Nov 2 Wrapped the runtime launch in try/catch so a failed start goes to the owner, and dropped the extensionEvent('workerStarted') call along the way. No extension heard that a worker started.

Verified

  • Checking out the commits one by one: right before 0c70c7a1 the fixture fails, from 0c70c7a1 on it passes.
