Does Codex need Claude's foreground-wait guard?

No. A note reaches a Codex worker while a long foreground command is still running, so there is nothing to guard. Codex has no guard; the docs now say why instead of implying one is missing.

Why Claude has the guard

Claude hands a waiting message to the agent only after its running tool call. A foreground sleep 300 would therefore keep the owner's note from the agent for five minutes, so Obeya refuses it.

What real Codex 0.162.0 does (scratch runs, 2 Nov 2026)

agent runs: sleep 120 && echo done (foreground) 7.2 s command inProgress 15.1 s Obeya sends a note (turn/steer) → accepted 19.5 s agent: "STEERED" ← 4 s later, command still running 19.7 s command is now a background terminal, process alive

Same result in every run. Without a note the agent just polls the command about every 30 s.
