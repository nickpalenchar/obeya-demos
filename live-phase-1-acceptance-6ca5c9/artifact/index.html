Live acceptance: Claude and Codex cards side by side

A scratch Obeya with real agents: one card on Claude Code (Sonnet), one on Codex (gpt-6.1-sol), started at the same time on the same canvas. Each card asks a question, hits the usage limit, gets paused, goes through two restarts of Obeya, then lands on main.

Each card kept one agent session the whole way through: the limit, the pause and both restarts did not start a new one.

Found and fixed: after hitting the usage limit, a Codex card didn't know when the limit would reset, so it just waited 15 minutes and tried again. Now it reads the reset time Codex gives and goes on at that time, the same as a Claude card does. The run above used the fixed version.

How the usage limit was tested

No real account was run down to its limit. Both agents reached their real models through a small local proxy, which turned their requests away for 150 seconds with the exact refusal each service sends when the account is out of quota. Everything else was real: Claude Code, the installed Codex, the models and Obeya.

Noticed along the way, not fixed here

  • On the Codex card, the work retrospective took the check that the owner's pause had killed for a timeout and suggested a longer one.
  • The Claude worker answered in German on an English task, before the owner had written anything. The Codex worker answered in English.
  • Obeya's process tracker froze the server for up to 1.8 s at a time while a Codex session was running.

Not covered: Linux and Windows, and an account that really runs out of quota.
