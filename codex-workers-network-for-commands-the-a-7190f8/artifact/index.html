Codex workers: network for allow-listed commands

A Codex worker runs in a sandbox without network. When a command needs the network, Codex asks for it. Now, if the repository's trusted allow list covers the command, Obeya grants network for that one command without asking you. Anything else still comes to you as a question.

Live check: real Codex workers in a scratch Obeya

The repository's trusted allow list held only Bash(pnpm install *). Two Codex workers were started.

What asks and what doesn't (unit tests)

Codex requestResult
Allow-listed command, network requested along with itruns, no question
Allow-listed command, network for one host (Codex's managed network)runs, no question
Allow-listed command chained with && (each part covered)runs, no question
Command not on the list (curl …, git push)asks
Chain with one uncovered part (source ~/.nvm/nvm.sh && pnpm install)asks
Network plus a path grant, or a path grant aloneasks
Permissions beyond networkasks
Input sent to an already running commandasks

When Obeya grants network, it grants it for that one command only. It never picks Codex's "for the whole session" or "always allow this host / command" options, even when Codex offers them.

Shell setup with nvm (added after your feedback)

Workers often start with source ~/.nvm/nvm.sh && nvm use 24 && …. Now that setup at the front needs no rule of its own, as long as what follows is on the list:

  • source (or .) goes through when the file exists outside everything the worker can write: its workspace, the demos folder and the temp folders. Symlinks are followed to the real file.
  • nvm use goes through with at most a version, --lts or --silent.
  • Rules may now use ~/, so Bash(source ~/.nvm/nvm.sh) works on every machine.

The same applies to obeya_run, the tool Codex workers use to run commands outside their sandbox.

Still asked: sourcing a file that doesn't exist yet, a relative path, a file in a temp folder, setup with nothing covered after it, setup in the middle of a chain, and other nvm commands (nvm install, extra flags).

The reader repository still needs a trusted allow list (for example pnpm -C * install * and pnpm -C * test) before any of this takes effect there.
